# PLAB 청구서 (tax.plab.life)

거래처에 링크로 보내는 청구서 페이지입니다.

- 거래처는 링크를 열어 청구서·입금 계좌를 확인하고, 정식 청구서를 인쇄·PDF로 저장할 수 있어요.
- 첫 거래라면 사업자등록증·통장사본을 직접 올리고, 문의를 남길 수 있어요.

| 구성 | 위치 | 역할 |
|---|---|---|
| 웹페이지 | 이 레포 (GitHub Pages) | `index.html`, `style.css`, `app.js`, `config.js` |
| 서버 | 구글 시트에 붙은 Apps Script | `apps-script/Code.gs` — 청구서 조회, 문의 저장, 서류 업로드, 슬랙 알림 |
| 데이터 | 구글 시트 'PLAB 청구서' | 청구서 · 품목 · 거래처 · 문의 탭 |
| 서류 | 운영팀 전용 드라이브 폴더 | 거래처가 올린 사업자등록증·통장사본 |

> 직인 이미지와 프랩 사업자등록증·통장사본은 공개 레포에 올리지 않습니다.
> 드라이브에 두고, 유효한 청구서 링크로 접속했을 때만 Apps Script가 내려줍니다.

---

## 1. 구글 시트 + Apps Script (최초 1회)

1. 회사 계정(plabsolution.com)으로 운영 공유 드라이브에 새 구글 시트 **PLAB 청구서**를 만듭니다.
2. 시트에서 **확장 프로그램 → Apps Script**를 엽니다. 기본 `Code.gs` 내용을 지우고 이 레포의 `apps-script/Code.gs`를 통째로 붙여넣은 뒤 저장합니다.
3. 드라이브에 아래를 준비합니다.
   - 거래처 서류를 모을 폴더 (예: `4. 회계/거래처 서류`) — **운영팀만 접근**
   - 직인 PNG 파일
   - 프랩 사업자등록증, 통장사본 파일
4. Apps Script **프로젝트 설정(톱니바퀴) → 스크립트 속성**에 추가합니다. ID는 드라이브 주소의 `/d/` 또는 `/folders/` 뒤 문자열입니다.

   | 속성 | 값 |
   |---|---|
   | `SLACK_WEBHOOK` | 세금계산서 요청 채널의 Incoming Webhook URL |
   | `DOCS_FOLDER_ID` | 거래처 서류 폴더 ID |
   | `SEAL_FILE_ID` | 직인 PNG 파일 ID |
   | `PLAB_BIZ_FILE_ID` | 프랩 사업자등록증 파일 ID |
   | `PLAB_BANK_FILE_ID` | 프랩 통장사본 파일 ID |

5. 편집기에서 함수 `setup`을 선택하고 **실행**합니다. 처음 실행할 때 권한 승인 창이 뜨면 허용합니다. 탭 4개와 예시 청구서가 만들어집니다.
6. **배포 → 새 배포 → 유형: 웹 앱**을 선택하고 아래처럼 설정한 뒤 배포합니다.
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
7. 나온 웹앱 URL(`…/exec`)을 `config.js`의 `API_URL`에 넣고 커밋합니다.

> 코드를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전**으로 다시 배포해야 반영됩니다.
> 이렇게 하면 URL은 그대로 유지됩니다.

## 2. GitHub Pages + 도메인

1. 레포 **Settings → Pages**에서 아래처럼 설정합니다.
   - Source: *Deploy from a branch*
   - Branch: `main` / `(root)`
2. 가비아 **DNS 관리 → 레코드 추가**에서 아래 레코드를 넣습니다.
   - 타입 `CNAME`, 호스트 `tax`, 값 `plab-solution.github.io.`
3. Pages 설정의 Custom domain에 `tax.plab.life`가 들어가 있는지 확인합니다. 레포의 `CNAME` 파일이 넣어줍니다. 인증서가 발급되면 **Enforce HTTPS**를 체크합니다.

## 3. 청구서 보내는 법

시트 머리글 중 **파란 칸은 스크립트가 채우는 칸**이고, 회색 칸만 직접 적으면 됩니다.

1. **청구서** 탭 새 줄의 **거래처 상호** 칸에 상호를 적습니다.
   - 기존 거래처는 드롭다운에서 고르세요. 사업자번호·대표자가 자동으로 채워집니다.
   - 새 거래처는 상호를 그대로 입력하세요. 구분이 `신규 · 서류 대기`로 표시됩니다.
   - 문서번호(`PLAB-연도-순번`), 발행일(오늘), 지급기한(+7일), 상태(입금 대기), 링크도 함께 채워집니다. 이미 값이 있는 칸은 건드리지 않아요.
2. 건명과 금액(VAT 별도)을 적습니다.
   - **품목이 하나면** 청구서 탭의 금액 칸이면 충분해요.
   - **품목이 여러 개면** 품목 탭에 같은 문서번호로 줄마다 적어요. 품목 탭에 줄이 있으면 그쪽이 우선이에요.
3. `링크` 열의 주소를 거래처에 보냅니다.
4. 입금이 확인되면 상태를 **입금 완료**로 바꿉니다. **취소**로 바꾸면 링크가 막혀요.
5. 세금계산서를 발행하면 **세금계산서 발행일** 칸에 날짜를 적습니다. 거래처 화면의 진행 단계가 완료로 바뀌어요.

거래처 화면은 `청구서 확인 → 입금 → 서류 제출 → 세금계산서 발행` 네 단계로 보여요. 상태가 입금 완료인지, 거래처 탭에 서류가 있는지, 세금계산서 발행일이 적혀 있는지에 따라 단계가 자동으로 넘어갑니다.

금액 계산은 아래와 같습니다.
- 부가세 = (공급가액 − 할인) × 10%
- 합계 = 공급가액 − 할인 + 부가세

## 4. 신규 · 기존 거래처

**거래처** 탭이 거래처 명부입니다. 사업자번호가 기준이에요.

| 구분 | 조건 | 거래처가 보는 화면 |
|---|---|---|
| 신규 · 서류 대기 | 청구서에 사업자번호가 없음 | "프랩과 첫 거래네요" + 기초 정보 등록하기 |
| 신규 | 서류를 낸 뒤 거래 1건 | "기초 정보가 등록돼 있어요" |
| 기존 | 거래 2건 이상, 또는 등록 경로가 `기존 자료` | "다시 찾아주셔서 감사해요 · N번째 거래" + 지난 청구서 목록 |

- **사이트 이전부터 거래하던 곳**은 거래처 탭에 사업자번호 · 상호 · 대표자를 넣고, 서류 두 칸에 파일 링크나 `기존 보관`을 적으세요. 등록 경로가 `기존 자료`가 되어 첫 청구서부터 기존 거래처로 보이고, 서류를 다시 달라고 하지 않아요.
- 거래처가 사이트에서 서류를 내면 거래처 탭에 자동으로 추가되고(`사이트 제출`), 드라이브의 `상호_사업자번호` 폴더에 저장되며, 슬랙에 `:new: 신규 거래처 서류 제출`로 알림이 갑니다.
- 구분 · 첫 거래일 · 거래 건수 · 최근 청구일 · 누적 청구액은 시트를 고칠 때마다 다시 계산돼요. 숫자가 이상하면 메뉴 **PLAB 청구서 → 거래처 집계 새로고침**을 누르세요.
- 문의 슬랙 알림에는 `[신규]` / `[기존]`이 붙어요.
- **세금계산서 이메일**: 거래처가 서류를 낼 때 세금계산서 받을 이메일도 함께 받아 거래처 탭 `세금계산서 이메일` 열에 저장해요. 서류는 있는데 이메일이 비어 있으면 거래처 화면에 이메일 입력 카드가 나와요. 이메일이 등록되면 슬랙으로 알려요.

## 4-1. 공용 거래처 등록 폼 (tax.plab.life/join)

청구서와 상관없이 **어느 거래처에나 같은 링크 하나**를 보내 서류를 주고받는 폼이에요. 매입처(프랩이 돈을 보내는 곳)와 매출처(프랩에 돈을 보내는 곳) 모두 이 링크를 쓰면 돼요.

- 거래처는 프랩 사업자등록증·통장 사본을 내려받고, 프랩이 세금계산서를 받는 이메일(`ops@plabsolution.com`)을 확인해요.
- 거래처는 거래 방식을 고르고 사업자 정보, 담당자, 서류를 올려요.
  - **프랩에 대금을 보내요**: 세금계산서 받을 이메일과 사업자등록증이 필수예요.
  - **프랩에서 대금을 받아요**: 사업자등록증과 통장 사본(입금받을 계좌)이 필수예요.
  - **둘 다**: 모두 필수예요.
- 제출하면 거래처 탭에 `등록 경로: 등록 폼`, `확인: 확인 대기`로 들어가고, 드라이브 `상호_사업자번호` 폴더에 서류가 저장되며, 슬랙에 알림이 와요.
- **운영팀이 서류를 보고 거래처 탭 `확인`을 `확인 완료`로 바꿔야** 청구서 화면에서 서류가 있는 거래처로 처리돼요. 누구나 제출할 수 있는 링크라서 이 확인 단계를 둬요.
- 이미 있는 거래처가 다시 제출하면 비어 있는 칸만 채우고, 서류가 이미 있으면 바꾸지 않고 폴더에만 저장해요.
- 장난 제출을 막으려고 전체 제출을 1시간에 30건, 같은 사업자번호는 1시간에 3건까지만 받아요.
- 프랩이 세금계산서를 받는 이메일은 스크립트 속성 `PLAB_TAX_EMAIL`로 바꿀 수 있어요(화면 표시는 `config.js`의 `taxEmail`).

청구서 화면에서도 **사업자등록증 하나만 있으면** 세금계산서 발행에 필요한 서류가 있는 것으로 봐요. 통장 사본은 프랩이 대금을 보낼 때만 필요해요.

## 5. 안전장치

- **요청 제한**: 같은 링크로 1시간에 문의 5번, 서류 제출 5번, 이메일 저장 5번, 사업자번호 확인 20번, 프랩 서류 받기 30번, 청구서 열기 120번까지 받아요. 넘으면 거래처 화면에 잠시 후 다시 하라는 안내가 나와요.
- **캐시**: 청구서 응답을 5분간 저장해 두고 빠르게 보내요. 시트를 고치면 캐시가 바로 비워져서 새 내용이 나가요.
- **집계 분리**: 시트를 고칠 때는 그 행만 다시 계산하고, 거래처 탭의 건수·누적액 같은 전체 집계는 1시간마다 돌아요. 바로 보고 싶으면 메뉴 **거래처 집계 새로고침**을 누르세요. 1시간 트리거는 `setup` 실행 시 또는 메뉴 **1시간마다 자동 집계 켜기**로 설치돼요.
- **입금일과 링크 보관**: 상태를 **입금 완료**로 바꾸면 **입금일**에 오늘 날짜가 들어가요. 입금일부터 30일이 지나면 그 링크에서는 **지난 청구** 목록이 숨겨져요. 기간은 스크립트 속성 `HISTORY_DAYS`로 바꿀 수 있어요.
- **링크 재발급**: 청구서 탭에서 행을 선택하고 메뉴 **선택한 청구서 링크 재발급**을 누르면 새 링크가 생기고, 예전 링크는 바로 열리지 않아요. 링크가 엉뚱한 곳에 전달됐을 때 쓰세요.
- **자동 칸 보호**: 링크ID · 문서번호 · 구분 · 링크 · 생성일(청구서 탭)과 집계 칸(거래처 탭)은 고치려 하면 경고창이 떠요. 정말 고칠 때만 확인을 누르세요. 보호가 풀렸으면 메뉴 **자동 칸 보호 다시 걸기**를 누르세요.
- **거래처 고르기**: 청구서 탭의 거래처 상호 드롭다운은 `상호 · 사업자번호` 형태예요. 사업자번호로 정확히 찾아서 대표자 등을 채우니, 이름이 같은 거래처도 헷갈리지 않아요. 새 거래처는 상호를 그대로 입력하세요.

## 6. 코드 자동 배포 (clasp + GitHub Actions)

`apps-script/` 폴더가 바뀌어 main에 올라오면 GitHub Actions가 Apps Script에 코드를 올리고, 지금 쓰는 웹앱을 새 버전으로 배포해요. 웹앱 URL은 그대로예요. 처음 한 번만 아래를 설정하세요.

1. https://script.google.com/home/usersettings 에서 **Google Apps Script API**를 **사용**으로 켜요.
2. Node.js가 설치된 PC에서 아래를 실행하고, 웹앱을 배포한 계정으로 로그인해요.
   ```
   npx @google/clasp@2.4.2 login
   ```
   로그인하면 사용자 폴더에 `.clasprc.json` 파일이 생겨요. Windows는 `C:\Users\내이름\.clasprc.json`이에요.
3. GitHub 레포 **Settings → Secrets and variables → Actions**에서 아래를 넣어요.
   - **Secrets** 탭 → `CLASPRC_JSON`: `.clasprc.json` 파일 내용 전체
   - **Variables** 탭 → `GAS_SCRIPT_ID`: Apps Script **프로젝트 설정 → ID**의 스크립트 ID
   - **Variables** 탭 → `GAS_DEPLOYMENT_ID`: 웹앱 URL에서 `/s/`와 `/exec` 사이 문자열
4. **Actions** 탭에서 **Apps Script 배포**를 한 번 직접 실행(Run workflow)해서 초록불이 뜨는지 확인해요.

> `.clasprc.json`에는 그 계정으로 Apps Script와 드라이브에 접근할 수 있는 토큰이 들어 있어요. 레포 시크릿에만 넣고 다른 곳에 올리지 마세요.
> 처음 자동 배포가 돌면 편집기의 `appsscript.json`이 레포 것으로 바뀌어요(시간대 Asia/Seoul, 웹앱은 배포한 사람 권한·누구나 접근).

## 7. 담당자가 바뀔 때

웹앱은 배포한 사람 계정 권한으로 돌아요. 그 계정이 정지되거나 권한이 바뀌면 거래처 화면이 열리지 않아요.

1. 새 담당자가 공유 드라이브에서 PLAB 청구서 시트를 열 수 있는지 확인해요.
2. 새 담당자 계정으로 Apps Script → **배포 → 새 배포 → 웹 앱**(실행: 나, 액세스: 모든 사용자)을 해요.
3. 새 URL을 `config.js`의 `API_URL`에 넣고 커밋해요. 자동 배포를 쓰면 `GAS_DEPLOYMENT_ID`와 `CLASPRC_JSON`도 새 담당자 것으로 바꿔요.
4. 메뉴 **1시간마다 자동 집계 켜기**를 새 담당자 계정으로 한 번 눌러요. 시간 트리거는 설치한 사람 권한으로 돌아요.
5. 이미 보낸 청구서 링크(tax.plab.life/?id=…)는 그대로 열려요.

## 화면만 확인하기

`config.js`의 `API_URL`이 비어 있거나 주소 끝에 `?demo=1`을 붙이면 예시 데이터로 화면을 볼 수 있어요. 기존 거래처 화면은 `?demo=1&as=existing`, 서류 없는 기존 거래처는 `?demo=1&as=nodocs`, 입금 완료는 `&paid=1`, 세금계산서 발행 완료는 `&tax=1`을 붙여 확인할 수 있어요.
